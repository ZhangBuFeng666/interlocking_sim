# 计算机联锁模拟仿真系统上台演示流程

## 一、演示准备

启动软件：

```bash
cd /Users/zbf/interlocking_sim
python3 main.py
```

如果双击启动，可打开：

```text
启动联锁模拟软件.command
```

开场说明：

```text
本系统把计算机联锁上位机、后台联锁逻辑和室外现场设备仿真集成在一台计算机中。界面上方是站场设备图，下面是列车/调车进路按钮、单道岔操作按钮和动态提示区。后台采用状态机方式实现进路检查、锁闭、信号开放、列车运行、解锁和异常拒绝。
```

## 二、演示总顺序

建议按以下顺序演示，能覆盖全部评分点：

1. 展示站场图完整性
2. 演示列车接车作业
3. 演示敌对进路拒绝
4. 演示列车出清和进路自动解锁
5. 演示发车或通过作业
6. 演示调车作业
7. 演示道岔单操、单锁、封锁
8. 演示取消进路和人工解锁倒计时
9. 演示信号机断丝仿真
10. 总结后台逻辑与仿真模块对应关系

## 三、详细演示步骤

### 1. 站场设备图形完整性显示

操作：打开软件后先不点击按钮，指向站场图说明设备。

讲解词：

```text
站场图按参考图绘制，包括左端 JXG、X、D1、IIAG，站内三条股道 3G、IIG、1G，右端 X3、XII、X1、D2、S、IIBG、JSG。左咽喉有 1、3、5 号道岔，右咽喉有 4、2 号道岔，左下方设置安全线和 PZA。轨道用金棕色表示，信号灯、按钮、道岔状态点都在图上标注。
```

这样演示的原因：

```text
评分中上位机第一项是站场设备图形完整性显示，因此先证明系统不是只有按钮，而是具有完整站场图、信号机、道岔、轨道区段和安全线。
```

可能问答：

| 老师问题 | 回答 |
|---|---|
| 为什么站场图不是图片，而是软件绘制？ | 因为站场设备需要动态变色，轨道占压、信号开放、道岔状态都要实时刷新，所以使用 Canvas 绘制对象，而不是静态图片。 |
| 图上哪些是现场设备？ | 轨道电路区段、信号机、道岔、安全线都属于现场设备仿真对象。 |

### 2. 办理列车接车作业

操作：点击 `办理 接车-X至IG`。

观察点：

```text
X 信号开放，相关道岔锁闭，列车 T1 出现在左端区段，轨道区段逐段变为占压颜色。
```

讲解词：

```text
这里演示列车接车进路。按钮下发到后台后，后台首先检查进路是否空闲、敌对进路是否未锁、轨道电路是否出清、道岔是否可用。条件满足后，锁闭相关道岔和进路，开放 X 信号机，并创建列车对象进入首区段。
```

这样演示的原因：

```text
该步骤同时覆盖列车按钮下发、接车作业办理、进路锁闭、信号开放、轨道占压和列车动态显示。
```

可能问答：

| 老师问题 | 回答 |
|---|---|
| 按钮点击后后台做了哪些检查？ | 检查进路是否已锁、敌对进路是否锁闭、相关轨道是否占压、道岔是否封锁或锁闭、道岔位置是否满足进路要求。 |
| 为什么要先锁道岔再开放信号？ | 这是联锁的基本安全原则，只有进路和道岔条件固定后，才能允许信号开放，防止列车进入未防护进路。 |

### 3. 演示敌对进路拒绝

操作：在接车进路未解锁时，点击 `办理 发车-IG至S` 或 `办理 通过-X至S`。

观察点：

```text
状态提示区显示拒绝原因，例如“与接车-X至IG敌对”或“进路已锁闭/区段占压”。
```

讲解词：

```text
这里演示后台联锁的安全防护。当前接车进路已经锁闭，如果再办理敌对进路，后台会根据冲突进路表拒绝办理，并在提示区给出原因。
```

这样演示的原因：

```text
只演示成功办理不够，联锁系统的核心是防止危险操作，所以必须展示非法操作会被后台拒绝。
```

可能问答：

| 老师问题 | 回答 |
|---|---|
| 敌对进路依据是什么？ | 每条进路配置了 conflicting_routes，办理新进路时会检查这些敌对进路是否锁闭。 |
| 如果轨道占压会怎样？ | 如果相关轨道电路处于占压状态，后台也会拒绝办理，提示具体占压区段。 |

### 4. 演示列车动态运行和进路自动解锁

操作：等待列车自动运行出清全进路。

观察点：

```text
列车 T1 按区段逐段移动，轨道电路先占压后出清。列车驶出后，信号关闭，进路和道岔自动解锁。
```

讲解词：

```text
仿真模块每秒触发一次 tick，驱动列车从当前区段移动到下一区段。列车离开区段时，该轨道电路出清；进入新区段时，该区段占压。当列车完整出清进路后，后台自动释放进路锁闭和道岔锁闭，并关闭信号。
```

这样演示的原因：

```text
该步骤对应站场动态显示、轨道电路占压/出清仿真、进路解锁功能，是评分点中的重点。
```

可能问答：

| 老师问题 | 回答 |
|---|---|
| 进路什么时候解锁？ | 当前实现为列车按进路区段顺序运行，最后一个区段出清后自动解锁。 |
| 轨道电路状态怎么变化？ | 列车进入区段置为占压，离开区段置为出清。 |

### 5. 演示发车或通过作业

操作一：接车进路出清后，点击 `办理 发车-IG至S`。

操作二：也可以直接点击 `办理 通过-X至S` 演示通过作业。

观察点：

```text
S 或 X 信号开放，列车按发车或通过进路移动，相关区段占压，出清后自动解锁。
```

讲解词：

```text
发车和通过作业与接车逻辑一致，都是先检查条件，再排列进路、锁闭道岔、开放信号、驱动列车运行，最后出清解锁。通过进路覆盖更长路径，用于展示列车连续通过站场。
```

这样演示的原因：

```text
后台逻辑评分要求接车、发车、通过完整过程，不能只演示一种列车作业。
```

可能问答：

| 老师问题 | 回答 |
|---|---|
| 接车、发车、通过的区别是什么？ | 区别在于进路起终点、使用信号机和轨道区段不同；后台使用统一的进路状态机处理。 |
| 为什么通过进路与接发车会冲突？ | 因为它们占用相同咽喉和股道资源，同时办理会导致列车运行路径冲突。 |

### 6. 演示站内调车作业

操作：点击 `办理 调车-D1至PZA`。

观察点：

```text
D1 调车信号开放，5 号道岔相关状态锁闭，调车车列运行到安全线/PZA 附近，出清后解锁。
```

讲解词：

```text
这里演示站内调车作业。调车进路使用 D1 调车信号，范围较短，主要涉及 D1G、S1G 和 5 号道岔。后台仍然执行区段出清、道岔可用、敌对进路检查。
```

这样演示的原因：

```text
评分中单独要求站内调车作业办理完整过程，因此需要演示调车信号和调车进路，而不是只演示列车进路。
```

可能问答：

| 老师问题 | 回答 |
|---|---|
| 调车作业和列车作业是否共用逻辑？ | 共用进路检查和锁闭/解锁框架，但进路类型、信号机和区段范围不同。 |
| 为什么调车也要检查敌对进路？ | 调车车列同样占用站内线路，如果与列车进路冲突也会产生安全风险。 |

### 7. 演示道岔单操、单锁、封锁

操作顺序：

1. 点击某组道岔的 `反操`，例如 `5` 号道岔。
2. 观察道岔显示为“转换中”，随后到达“反位”。
3. 点击 `单锁`。
4. 再点击 `定操` 或 `反操`。
5. 观察提示区显示“道岔锁闭，拒绝单操”。
6. 点击 `单解`。
7. 点击 `封锁`。
8. 尝试办理涉及该道岔的进路。
9. 观察提示区显示“道岔封锁，拒绝办理”。
10. 点击 `解封` 恢复。

讲解词：

```text
道岔单操用于人工将道岔转换到定位或反位。后台会检查道岔是否锁闭、封锁以及岔区是否占压。单锁表示人为固定道岔位置，防止误动；封锁表示设备故障或施工防护，封锁后相关进路不能办理。
```

这样演示的原因：

```text
该步骤覆盖道岔单操、单锁、封锁逻辑，同时展示室外道岔设备动作和位置状态仿真。
```

可能问答：

| 老师问题 | 回答 |
|---|---|
| 单锁和封锁有什么区别？ | 单锁主要是锁住道岔不允许单独转换；封锁表示设备不可用，既禁止单操，也禁止涉及该道岔的进路办理。 |
| 道岔转换为什么不是瞬间完成？ | 为了模拟现场转辙机动作过程，系统设置了“转换中”状态，经过仿真节拍后到达定位或反位。 |
| 岔区占压时能不能扳道岔？ | 不能。后台会检查相关轨道电路，占压时拒绝单操。 |

### 8. 演示取消进路和人工解锁

操作一：办理一条进路后，在列车尚未进入或刚办理时点击 `取消`。

观察点：

```text
信号关闭，状态区显示正常取消倒计时，倒计时结束后进路解锁。
```

操作二：办理一条进路且列车已经占压后，点击 `取消`。

观察点：

```text
普通取消被拒绝，提示进路占用，需要人工解锁。
```

操作三：点击 `人工解锁`。

观察点：

```text
状态区显示 5 秒人工解锁倒计时，倒计时结束后释放进路和道岔锁闭。
```

讲解词：

```text
取消进路分为正常取消和人工解锁。正常取消用于进路未占用的情况，风险较低，倒计时较短；当进路已经占用时，普通取消会被拒绝，需要人工解锁，并设置更长倒计时，模拟现场安全延时。
```

这样演示的原因：

```text
评分中明确要求取消进路功能含人工解锁，并且要求倒计时和操作提示功能。
```

可能问答：

| 老师问题 | 回答 |
|---|---|
| 为什么进路占用时不能普通取消？ | 因为列车已经进入进路，直接取消可能造成防护丢失，所以普通取消必须拒绝。 |
| 人工解锁为什么有倒计时？ | 模拟联锁系统中的安全延时，给现场确认和列车防护留出时间。 |

### 9. 演示信号机开放、关闭、断丝仿真

操作顺序：

1. 点击 `X断丝/恢复`。
2. 办理 `接车-X至IG`。
3. 观察 X 信号机显示为断丝状态，而不是正常开放状态。
4. 再点击 `X断丝/恢复` 恢复。

讲解词：

```text
信号机有关闭、开放、断丝三种状态。正常办理进路时，防护信号开放；进路解锁后信号关闭。如果信号机被设置为断丝，后台可以收到开放命令，但现场设备显示为故障断丝状态，界面用故障颜色提示。
```

这样演示的原因：

```text
该步骤覆盖仿真功能中信号设备开放、关闭、断丝状态仿真。
```

可能问答：

| 老师问题 | 回答 |
|---|---|
| 断丝和关闭有什么区别？ | 关闭是正常红灯或禁止显示；断丝是设备故障，表示信号命令与现场显示不一致或灯丝故障。 |
| 断丝后还能办理进路吗？ | 当前仿真允许后台命令执行，但界面保持断丝故障显示，用于展示现场设备故障状态。 |

## 五、结束总结词

```text
本系统完成了单机计算机联锁模拟软件。上位机负责站场显示和按钮操作，后台联锁逻辑负责进路检查、道岔锁闭、信号开放、取消和解锁，仿真模块负责信号机、道岔和轨道电路状态变化。演示中可以看到，合法操作能够办理进路并驱动列车运行，非法操作会被后台拒绝并给出提示，从而体现了计算机联锁系统的安全控制思想。
```
