# 计算机联锁模拟仿真系统设计方案

## 1. 系统目标

本系统在一台计算机上完成计算机联锁模拟仿真，包含上位机界面、后台逻辑联锁软件和现场设备仿真。实现对象覆盖列车接发、通过、站内调车、进路锁闭/解锁/人工解锁、道岔单操/单锁/封锁、信号机与轨道电路状态仿真。

## 2. 上位机设计

### 2.1 站场设备图

站场按原始参考图抽象为三股道、左右咽喉和安全线，GUI 使用 1200×380 Canvas 绘制：

```text
JXG -- IIAG -- 1 -- 3 ---------------------- 4 -- 2 -- IIBG -- JSG
                 \  3G ------------------- /      /
                  \ IIG ------------------/------/
                   \ 1G ------------------------/
安全线 -- PZA -- 5 -- 1G
```

设备标注：

| 类型 | 名称 | 位置/含义 |
|---|---|---|
| 道岔 | 1、2、3、4、5 | 五个独立道岔对象，分别具有定位、反位、转换中、单锁、封锁和进路锁闭状态 |
| 信号机 | X、S | 左端进站、右端出站主信号机 |
| 信号机 | D1、D2 | 调车信号机 |
| 信号机 | S1、S3、SII、X1、XII、X3 | 股道及方向信号显示，带紫色按钮方块 |
| 终端点 | PZA | 安全线附近终端按钮/终端点，使用灰色空心圆表示 |
| 轨道电路 | JXG、IIAG-A/B、3G-L/M/R、IIG-L/M/R、1G-L/M/R、IIBG-A/B、JSG、安全线-A/B | 细分轨道电路，支持车列逐段占压/出清 |
| 列车 | T1、T2... | 随进路自动生成并沿轨道电路移动 |

### 2.2 按钮布局

上位机界面分为三个区域：

| 区域 | 按钮/显示 | 功能 |
|---|---|---|
| 列车/调车进路按钮 | 办理、取消、人工解锁 | 触发接车、发车、通过和调车进路逻辑 |
| 单道岔操作区 | 定操、反操、单锁、单解、封锁、解封 | 对 1/3、2/4、5 号道岔单独操作 |
| 动态提示/状态区 | 进路锁闭、倒计时、日志 | 显示列车移动、道岔转换、信号开放/关闭、错误提示 |

### 2.3 动态显示设计

动态显示采用 Tkinter Canvas：

| 对象 | 显示策略 |
|---|---|
| 轨道电路 | 棕色表示出清，蓝色表示进路锁闭，红色表示占压 |
| 信号机 | 灰色关闭，绿色开放，橙色断丝 |
| 道岔 | 紫色定位，粉色反位，黄色转换中；锁闭、单锁、封锁通过边框和状态面板显示 |
| 列车 | 蓝色车体，标注 T1/T2，按仿真节拍从一个区段移动到下一区段 |
| 倒计时 | 取消进路 2s，人工解锁 5s，在状态区实时递减 |
| 操作提示 | 最近 8 条事件或拒绝原因滚动显示 |

## 3. 后台逻辑设计

### 3.1 列车接发及通过流程

```text
点击办理列车进路
  -> 检查进路是否已锁
  -> 检查敌对进路是否锁闭
  -> 检查所有轨道电路是否出清
  -> 检查道岔是否封锁/占压
  -> 道岔不在要求位置则转换
  -> 锁闭道岔和进路
  -> 开放防护信号机
  -> 创建列车并进入首区段
  -> 按仿真节拍运行
  -> 列车完整出清后自动解锁进路并关闭信号
```

### 3.2 站内调车作业流程

```text
点击办理调车进路
  -> 检查 D1/D2 对应进路条件
  -> 检查调车范围区段出清
  -> 检查调车道岔 5 是否可用
  -> 锁闭调车进路和道岔
  -> 开放调车信号
  -> 调车车列进入目标区段
  -> 出清后自动解锁
```

### 3.3 进路锁定、解锁及人工解锁

| 逻辑 | 条件 | 动作 |
|---|---|---|
| 锁定 | 区段出清、敌对未锁、道岔可转且到位 | `route.locked=True`，相关道岔 `locked=True`，信号开放 |
| 正常解锁 | 列车/调车车列顺序出清全部区段 | 信号关闭，进路和道岔解锁 |
| 取消进路 | 进路未占用 | 信号关闭，2 秒倒计时后解锁 |
| 人工解锁 | 进路占用或非正常处理 | 信号关闭，5 秒倒计时后强制解锁 |

### 3.4 道岔单操、单锁、封锁逻辑

| 操作 | 允许条件 | 拒绝条件 |
|---|---|---|
| 定操/反操 | 道岔未锁、未封、岔区未占压 | 进路锁闭、封锁、岔区占压 |
| 单锁 | 调度员人工锁闭道岔 | 后续单操被拒绝 |
| 单解 | 解除单锁 | 不自动改变位置 |
| 封锁 | 设备故障或施工防护 | 进路办理和单操均被拒绝 |
| 解封 | 故障恢复 | 恢复进路办理条件 |

## 4. 仿真功能设计

### 4.1 信号机状态仿真

信号机包含关闭、开放、断丝三态。若信号机断丝，后台禁止建立需要开放该信号的进路，并在提示区显示拒绝原因；界面用橙色灯和“断丝”文字提示故障。

### 4.2 道岔动作及位置状态仿真

道岔包含定位、反位、转换中三态。单操或进路自动选排时，若目标位置不同，先进入转换中，2 个仿真节拍后到达目标位置。锁闭或封锁状态会阻止转换。

### 4.3 轨道电路占压与出清仿真

列车进入区段时该轨道电路置为占压，离开时置为出清。进路办理前必须验证所有相关区段出清；人工出清接口用于异常恢复和测试。

## 5. 系统集成设计

### 5.1 模块接口

| 调用方向 | 接口 | 说明 |
|---|---|---|
| 上位机 -> 后台 | `request_route(route_name)` | 办理列车/调车进路 |
| 上位机 -> 后台 | `cancel_route(route_name, manual)` | 取消或人工解锁进路 |
| 上位机 -> 后台 | `move_switch(name, target)` | 道岔定操/反操 |
| 上位机 -> 后台 | `set_switch_lock/block()` | 单锁、单解、封锁、解封 |
| 上位机 -> 后台 | `set_signal_broken()` | 信号机断丝/恢复 |
| 后台 -> 仿真 | `tick()` | 每秒驱动道岔、列车、倒计时状态变化 |
| 仿真 -> 上位机 | `StationState` | GUI 从统一状态模型读取并刷新显示 |

### 5.2 异常处理策略

| 异常 | 处理 |
|---|---|
| 敌对进路 | 拒绝办理并提示冲突进路名称 |
| 轨道占压 | 拒绝办理，提示占压区段 |
| 道岔锁闭 | 拒绝单操，保持原状态 |
| 道岔封锁 | 拒绝进路和单操 |
| 信号断丝 | 允许后台命令执行，但现场显示断丝并保持故障提示 |
| 占用进路取消 | 普通取消拒绝，提示使用人工解锁 |

### 5.3 操作顺序设计

推荐演示顺序：先办理“X至IIG接车”，观察 X 开放、进路蓝色锁闭和列车逐段占压；再尝试“X至S通过”验证敌对拒绝；待列车出清后办理发车；随后演示调车、道岔单操/单锁/封锁、人工解锁和信号断丝。

| `main.py` | 软件启动入口 |

| 后台：列车接车、发车及通过 | 10% | `X至3G接车`、`X至IIG接车`、`X至1G接车`、`3G/IIG/1G至S发车`、`X至S通过` 及列车运行释放逻辑 |
