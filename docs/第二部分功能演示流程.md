## 演示前准备

在项目根目录运行：

```bash
python main.py
```

推荐使用桌面 Tkinter 界面演示。若当前 Python 缺少 Tkinter，程序会自动打开浏览器界面 `http://127.0.0.1:8765`，多数后台功能仍可演示；但桌面界面按钮更完整，包含“自动解锁”“清除所有进路”“模拟列车出清”等演示按钮。

演示时主要观察三个位置：

1. 站场图轨道颜色：棕色为出清，蓝色为进路锁闭，红色为轨道占压。
2. 信号机颜色：灰色为关闭，绿色为开放，橙色为断丝。
3. 右侧“动态提示/状态”：显示进路锁闭、倒计时、道岔状态、轨道状态和拒绝原因。

## 1. 列车接车、发车及通过作业办理完整过程

### 是否实现

已实现。

代码依据：

| 内容 | 代码位置 |
|---|---|
| 接车进路 | `model.py`：`X至3G接车`、`X至IIG接车`、`X至1G接车` |
| 发车进路 | `model.py`：`3G至S发车`、`IIG至S发车`、`1G至S发车` |
| 通过进路 | `model.py`：`X至S通过` |
| 办理逻辑 | `interlocking.py`：`request_route()` |
| 列车运行与自动释放 | `interlocking.py`：`_tick_trains()`、`_release_route()` |

后台办理时会检查：进路是否已锁闭、信号机是否断丝、敌对进路是否锁闭、轨道是否占压、道岔是否封锁或单锁、道岔是否已被其他进路锁闭。条件满足后，锁闭进路和道岔，开放信号，并创建列车沿进路运行。

### 演示流程

#### 接车作业

1. 点击“重置系统”，保证所有设备处于初始状态。
2. 点击“接车至 IIG”。
3. 观察 X 信号机变绿，相关轨道变蓝，列车 T1 出现在左侧区段。
4. 观察列车逐段移动，经过的轨道变红，占压后又恢复。
5. 等列车完全驶出后，观察进路自动解锁，X 信号关闭，轨道恢复出清。

讲解重点：后台收到接车办理命令后，先做联锁条件检查，再锁闭进路、开放 X 信号，最后驱动列车运行。

#### 发车作业

1. 确认当前没有锁闭进路。
2. 点击“IIG 发车”。
3. 观察 SII 信号开放，IIG 方向至右端出站方向相关区段锁闭。
4. 等列车逐段运行到 JSG 方向并出清。
5. 观察进路和道岔自动解锁，信号关闭。

讲解重点：发车作业和接车作业共用同一套 `request_route()` 联锁检查流程，只是进路起终点、信号机和轨道区段不同。

#### 通过作业

1. 点击“重置系统”。
2. 点击“通过作业”。
3. 观察 X 信号开放，左端 JXG 经 IIG 到右端 JSG 的长进路被锁闭。
4. 观察列车从左端进入，连续通过站内到右端出清。
5. 等待自动解锁。

讲解重点：通过进路覆盖更长路径，可证明系统不只支持单一接车或发车，而是支持列车完整通过站场。

### 可补充演示：敌对进路拒绝

1. 点击“接车至 IIG”。
2. 在进路未解锁时，立即点击“通过作业”。
3. 观察右侧提示出现“敌对”“占压”或“进路已锁闭”等拒绝原因。

该步骤能突出后台联锁软件的安全防护能力。

调车进路与列车进路共用后台联锁检查、锁闭、信号开放、车列运行和出清解锁逻辑。

### 演示流程

1. 点击“重置系统”。
2. 点击“D1 至 1G 调车”。
3. 观察 D1 调车信号开放，相关轨道锁闭，调车车列开始运行。

5. 点击“D2 至 IIG 调车”，重复观察调车信号开放、区段占压和自动解锁。
6. 点击“安全线调车”，观察 5 号道岔相关进路和安全线区段变化。

讲解重点：调车作业不是简单动画，后台仍然要检查轨道出清、敌对进路、道岔状态和信号状态，条件满足才允许办理。

### 可补充演示：调车被封锁道岔拒绝

2. 在“道岔5”一行点击“封锁”。

5. 点击“道岔5”的“解封”恢复。

该步骤能证明调车作业同样受到道岔封锁条件约束。

## 3. 取消进路功能，含人工解锁

### 是否实现

已实现。

代码依据：

| 内容 | 代码位置 |
|---|---|
| 普通取消 | `interlocking.py`：`cancel_route(manual=False)` |
| 人工解锁 | `interlocking.py`：`cancel_route(manual=True)` |
| 倒计时递减 | `interlocking.py`：`_tick_routes()` |
| 倒计时结束释放 | `interlocking.py`：`_release_route()` |

普通取消逻辑：进路未占用时允许取消，设置 2 秒倒计时，倒计时结束后解锁。

人工解锁逻辑：进路占用时普通取消被拒绝，人工解锁设置 5 秒倒计时，倒计时结束后释放进路和道岔锁闭。

### 演示流程 A：普通取消

1. 点击“重置系统”。
2. 点击“接车至 3G”。
3. 立即点击“取消当前进路”。
4. 观察 X 信号关闭，右侧状态显示该进路倒计时 2 秒。
5. 等待 2 秒，观察进路变为“未锁”，道岔锁闭解除。

注意：进路建立后列车会延迟进入首区段，点击“取消当前进路”要在列车进入首区段前完成；若已经出现轨道占压，则普通取消会被拒绝，需要改用人工解锁演示。

### 演示流程 B：占用进路普通取消被拒绝

1. 点击“重置系统”。
2. 点击“接车至 1G”。
3. 等待列车占压进路内任一区段。
4. 点击“取消当前进路”。
5. 观察提示“进路占用，需人工解锁”。

### 演示流程 C：人工解锁

1. 保持上一步进路占用状态。
2. 点击“人工解锁”。
3. 观察状态区显示 5 秒倒计时。
4. 等待倒计时结束。
5. 观察进路解锁、信号关闭、道岔解除锁闭。

讲解重点：普通取消和人工解锁的区别在于进路是否占用，以及安全延时不同。占用时不能直接普通取消，必须走人工解锁流程。

## 4. 道岔单操、单锁及封锁逻辑功能

### 是否实现

已实现。

代码依据：

| 内容 | 代码位置 |
|---|---|
| 道岔定操、反操 | `interlocking.py`：`move_switch()` |
| 道岔单锁、单解 | `interlocking.py`：`set_switch_lock()` |
| 道岔封锁、解封 | `interlocking.py`：`set_switch_block()` |
| 道岔转换中和到位 | `interlocking.py`：`_tick_switches()` |

单操前会检查：道岔是否被进路锁闭、是否单锁、是否封锁、相关岔区轨道是否占压。任一条件不满足都会拒绝转换并给出提示。

### 演示流程 A：道岔单独转换

1. 点击“重置系统”。
2. 找到“道岔5”一行。
3. 点击“反操”。
4. 观察 5 号道岔显示“转换中”，状态区提示“道岔5向反位转换”。
5. 等待约 2 秒，观察道岔到达“反位”。
6. 点击“定操”，观察道岔再转换回“定位”。

### 演示流程 B：单锁后拒绝单操

1. 点击“重置系统”。
2. 点击“道岔5”的“单锁”。
3. 再点击“道岔5”的“反操”。
4. 观察状态区提示“拒绝单操5: 道岔单锁”。
5. 点击“单解”恢复。

### 演示流程 C：封锁后拒绝单操和相关进路

1. 点击“重置系统”。
2. 点击“道岔5”的“封锁”。
3. 点击“道岔5”的“反操”。
4. 观察提示“拒绝单操5: 道岔封锁”。
5. 再点击“安全线调车”。
6. 观察提示“拒绝安全线调车: 道岔5封锁”。
7. 点击“道岔5”的“解封”恢复。

讲解重点：单锁主要防止道岔被单独扳动；封锁表示设备不可用，既阻止单操，也阻止涉及该道岔的进路办理。

## 5. 进路解锁功能

### 是否实现

已实现。

代码依据：

| 解锁方式 | 代码位置 |
|---|---|
| 列车完整出清后自动解锁 | `interlocking.py`：`_tick_trains()`、`_release_route()` |
| 手动点击自动解锁 | `interlocking.py`：`auto_unlock()` |
| 取消或人工解锁倒计时结束解锁 | `interlocking.py`：`_tick_routes()`、`_release_route()` |

解锁动作包括：进路 `locked=False`，相关道岔 `locked=False`，防护信号关闭，当前进路清空。

### 演示流程 A：列车出清后自动解锁

1. 点击“重置系统”。
2. 点击“通过作业”。
3. 观察进路锁闭、信号开放、列车运行。
4. 不做其他操作，等待列车从最后一个区段驶出。
5. 观察状态区提示“列车T1驶出进路X至S通过”和“进路X至S通过解锁，信号关闭”。
6. 观察轨道恢复出清，道岔解除进路锁闭。

### 演示流程 B：轨道仍占压时自动解锁被拒绝

1. 点击“重置系统”。
2. 点击“接车至 IIG”。
3. 在列车还在进路上时点击“自动解锁”。
4. 观察提示“拒绝自动解锁X至IIG接车: 轨道仍占压”。

### 演示流程 C：模拟出清后自动解锁

1. 保持上一步的进路锁闭状态。
2. 点击“模拟列车出清”。
3. 点击“自动解锁”。
4. 观察进路解锁，信号关闭，道岔解锁。

讲解重点：进路解锁不是简单清屏，而是按轨道占压状态判断。轨道仍占压时拒绝自动解锁，全部出清后才允许释放。

## 五项功能缺失情况

未发现第二部分五项后台联锁功能缺失。

需要注意的演示差异：

1. 桌面 Tkinter 界面功能按钮最完整，推荐使用 `python main.py` 启动后在桌面界面演示。
2. 浏览器备用界面能办理进路、取消、人工解锁、道岔单操、单锁、封锁和信号断丝，但没有桌面界面的“自动解锁”“模拟列车出清”等辅助按钮，因此演示第五项“进路解锁功能”时最好使用桌面界面。
3. `docs/design.md` 中个别文字提到“信号断丝允许后台命令执行”，但当前实际代码和测试是“信号断丝时拒绝办理相关进路”，这与 `docs/requirements_mapping.md` 的说明一致，也更符合后台联锁安全逻辑。

1. 接车：点击“接车至 IIG”，说明检查、锁闭、开放信号、列车运行。

7. 道岔逻辑：演示 5 号道岔反操、单锁拒绝、封锁拒绝安全线调车。
